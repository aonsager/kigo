## 2. Testing workflow

This repo runs an autonomous "afk loop": a wrapper script (`scripts/afk-run.sh`)
repeatedly invokes a headless `claude -p` session, one loop iteration at a time,
in a `while` loop. Iterations are strictly sequential. Each iteration builds and
runs the app's XCTest suites on an iOS Simulator.

The project (`Kigo.xcodeproj`) is generated by XcodeGen from `project.yml`. The
hardened test command used (from `CLAUDE.md`):

```bash
xcodegen generate
perl -e 'alarm shift; exec @ARGV' 720 \
  xcodebuild test \
    -scheme Kigo \
    -destination 'platform=iOS Simulator,name=iPhone 17,OS=26.4.1' \
    -test-timeouts-enabled YES \
    -default-test-execution-time-allowance 120 \
    -maximum-test-execution-time-allowance 300 \
    CODE_SIGNING_ALLOWED=NO \
    -only-testing:KigoTests/<SuiteName>
```

- The runtime is pinned to `OS=26.4.1` (deliberately off the iOS 26.5 runtime).
- The iOS 26.5 runtime is kept installed because Xcode 26.5 refuses to enumerate
  any iOS simulator destination unless its own platform is present; it is
  installed but never the test target.
- A `perl alarm` wrapper caps a single-suite run at 720s.
- The wrapper's overall per-iteration timeout is `AFK_ITER_TIMEOUT=2700s`; a
  SIGALRM kill at that boundary is logged as `rc=142`.

### Between-iteration simulator cleanup

`scripts/afk-run.sh` runs `reap_sim_debris()` at the start of every iteration,
before dispatching the session. Its comment states iterations are sequential so
nothing is using the simulator at that point. Verbatim (lines 74-84):

```bash
reap_sim_debris() {
  command -v xcrun >/dev/null 2>&1 || return 0
  xcrun simctl shutdown all       >/dev/null 2>&1 || true
  xcrun simctl delete unavailable >/dev/null 2>&1 || true
  local n
  n="$(pgrep -f 'CoreSimulator' 2>/dev/null | wc -l | tr -d ' ')"
  if [ "${n:-0}" -gt 30 ]; then
    log "sim cleanup: ${n} CoreSimulator processes accumulated — hard service reset"
    killall -9 com.apple.CoreSimulator.CoreSimulatorService 2>/dev/null || true
  fi
}
```

The wrapper log shows this `killall -9` threshold (`>30`) is crossed on nearly
every iteration; logged counts were consistently 73-77 CoreSimulator processes.

4. **Idle `killall -9 CoreSimulatorService`** (the wrapper's exact command), run

   - `simdiskimaged` unaffected: still pid 80495, `state = running`,

   - CoreSimulatorService not running afterward (it is on-demand).
   - Next `xcrun simctl list devices booted` succeeded (rc=0).
   - CoreSimulator process count unchanged (~70-71).
   - Result: no orphan, no wedge.

5. **`killall -9 CoreSimulatorService` during an in-flight simctl operation**

6. **`xcodebuild -showdestinations` health over the session:** succeeded before
